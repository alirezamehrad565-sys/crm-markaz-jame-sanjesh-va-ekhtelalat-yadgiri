# web-game-dev — ساخت بازی HTML5 با موتور واقعی (نسخهٔ ۱)

اسکیل ساخت بازی وب با کیفیت حرفه‌ای برای پروژه‌های درمانی/آموزشی کودک.
مصرف: هر بار که قرار است بازی جدید ساخته شود، بازی موجود «جوس» بگیرد، یا موتور بازی ارتقا یابد.

---

## ۱) انتخاب موتور — ماتریس تصمیم

| موتور | باندل min | gz | کی استفاده کنیم | کی نه |
| --- | --- | --- | --- | --- |
| **Phaser 3** | ~۱.۴MB | ~۳۵۰KB | بازی 2D کامل: تویین، پارتیکل، دوربین، صحنه، ورودی — همه از جعبه؛ سریع‌ترین راه به کیفیت دیده‌شده | اگر کل صفحه < ۱۰۰KB باید باشد |
| **PixiJS 8** | ~۴۵۰KB | ~۱۲۰KB | فقط رندر WebGL لازم است؛ لایهٔ جوس خودمان را می‌نویسیم | تویین/پارتیکل/صحنه ندارد — وقت مهندسی می‌برد |
| **Kaplay** | ~۳۰۰KB | ~۹۰KB | بازی تفننی سریع، پیش‌نمایش | اکوسیستم کوچک، کنترل کم |
| **PlayCanvas** | موتور + ادیتور ابری | — | سه‌بعدی/تیم | نیازمند ادیتور ابری؛ CSP بسته نمی‌خواهد |
| **Three.js** | ~۶۵۰KB | ~۱۶۰KB | واقعاً 3D | بازی 2D وکتوری |
| **DOM/CSS** | ~۰ | ~۰ | کارت، فرم، متن RTL | صحنهٔ زندهٔ بازی |
| **میکرو-انجین داخلی (ve.js)** | ~۵KB | ~۵KB | ساعت واکنش، حلقهٔ rAF، شکل پایه | جوس سنگین را خودت بنویسی |

**قانون پروژهٔ ما (تصمیم ۱.۱.۰):** انجین پایهٔ سبک `ve.js` برای *قرارداد بالینی* (ساعت واکنش §۷، visibility، زمان‌بندی) می‌ماند؛
**Phaser 3 وندورشدهٔ هم‌مبدأ** برای *رندر صحنه* لایه‌بندی می‌شود: `engine/phaser.min.js` با `import()` تنبل فقط وقتی بازی می‌آید،
و اگر موتور لود نشد، پخش‌کننده به رندر SVG ایستا برمی‌گردد (جمع‌آوری دادهٔ بالینی هرگز نمی‌میرد).
چرا Phaser و نه Pixi؟ تویین/پارتیکل/ایسیینگ آماده و بی‌باگ یعنی کیفیت در چند ساعت، نه چند روز؛ باندل ۳۵۰KB gz فقط روی
صفحهٔ اختصاصی بازی لود می‌شود (باندل بوت سامانهٔ اصلی را نمی‌زند) و کلادفلر آن را brotli می‌کند.

چرا وندور و نه CDN؟ CSP صفحهٔ کودک `default-src 'none'` است؛ فقط هم‌مبدأ مجاز است.

## ۲) لایه‌بندی اجباری (پروژهٔ games)

```
DOM (play.js)  → پروتکل، شبکه، ساعت، کارت‌ها، حباب بازخورد   ← هرگز به Phaser نمی‌رود
Canvas (world.js) → آسمان، شخصیت، محرک، پارتیکل، جوس          ← هرگز fetch/protocol ندارد
engine/ve.js   → ساعت واکنش، visibility، PALETTE/SHAPES        ← قرارداد بالینی ثابت
```

- محرک از `ve.js SHAPES` می‌آید؛ در world با `Path2D` روی canvas آفسکرین رستری و با `textures.addCanvas` می‌شود اسپرایت —
  تک‌منبع هنری، دو رندر (SVG فال‌بک + کانواس).
- DPR: بوم = اندازهٔ CSS × `min(devicePixelRatio,2)`؛ ریشهٔ صحنه `setScale(dpr)`؛ مختصات طراحی بر حسب CSS-px.
- ResizeObserver + `game.scale.resize` (حالت Scale.NONE) — نه FIT، نه Interval.
- تایمرها فقط Phaser (`delayedCall`/`tweens`) یا انجین؛ **هرگز setInterval**.
- کل صحنه لمس است؛ شنوندهٔ لمس در DOM (play.js) می‌ماند — canvas رویداد را بالاubb می‌کند.

## ۳) اصول بالینی که جوس را محدود می‌کند (غیرقابل مذاکره)

1. **بی‌صدا** — صدا فقط بعد از M6 (R2) و با کلید بالینی.
2. **آرامش در پنجرهٔ محرک، جوس در فاصلهٔ بازخورد** — موقع نمایش محرک پس‌زمینه ساکت/کم‌نور (calm mode)؛
   انفجار پارتیکل فقط بعد از پاسخ. محرک هرگز با جنبش حواس‌پرت‌کن همزمان نیست.
3. **بدون عدد/رتبه/تایمر/استریک** (TONE_RULES) — پاداش = ستاره، درخشش، شخصیت؛ نه «+۱» و نه شمارنده.
4. **دو نشانهٔ رنگ+شکل** برای کوررنگی؛ پالت نام‌دار از ve.js.
5. **کاهش‌جنبش** — `prefers-reduced-motion` همهٔ تویین/پارتیکل را خاموش می‌کند (نمایش/محو ساده).
6. **بدون سرزنش** — خطا = لحن نرم (متن از سرور)، جلوهٔ خاکستری ملایم، نه فلش قرمز.
7. هدف لمسی ≥۶۴px؛ بدون فلاش/شبح؛ هیچ انیمیشن زیر ~۳۰۰ms با کنتراست بالا.
8. ممنوع در متن کودک: فهرست FORBIDDEN_TEXT_PATTERNS (شکست، اشتباه کردی، سریع‌تر، تایمر، …).

## ۴) چک‌لیست جوس (حداقل کیفیت قابل قبول برای یک بازی کودک)

- [ ] ورود محرک: pop-in با `Back.easeOut` (~۴۵۰ms) + سایهٔ زمین که با نفس‌کشیدن هم‌فشار می‌شود
- [ ] نفس کشیدن: `yoyo sine` مقیاس ۱↔۱٫۰۴ و شناوری ±۶px (دورهٔ ≥۲s)
- [ ] موفقیت GO: انفجار ۱۲-۱۸ پارتیکل ستاره‌ای + حلقهٔ شوک + درخشش هاله + اسکواش محرک
- [ ] بازداری درست NOGO: سپر درخش + ۳-۶ جرقهٔ ملایم + حباب تشویق سرور
- [ ] خطا: فروپاشی خاکستری-آبی نرم، نگرانیِ ملایم شخصیت
- [ ] شخصیت همیشه‌حاضر (شب‌تاب «چراغک»): پلک‌زدن، شناوری، سه خلق (شادی/تشویق/نگرانی)
- [ ] پس‌زمینهٔ زنده ولی آرام: آسمان گرادیانی + ستاره‌های چشمک‌زن آهسته + ابر کم‌رنگ
- [ ] پایان: باران ستارهٔ طلایی آرام + کارت DOM محترمانه (بدون «یک دور دیگر»)
- [ ] همهٔ مقادیر زمانی در یکجای ماژول؛ فال‌بک SVG ایستا اگر موتور نیامد (سقف ۶s)

## ۵) الگوهای آماده

**رستری مسیر SVG → اسپرایت:**
```js
const c = document.createElement('canvas'); c.width = c.height = S; // S = اندازه × ۱.۵ برای وضوح
const x = c.getContext('2d'); const p = new Path2D(d);
x.scale(S/120, S/120); x.fillStyle = fill; x.fill(p);
x.lineWidth = 2.5; x.strokeStyle = INK; x.lineJoin = 'round'; x.stroke(p);
scene.textures.addCanvas(key, c);
```

**گرادیان آسمان:** canvas آفسکرین ۸×۵۱۲ با createLinearGradient → `textures.addCanvas` → tileSprite.

**پارتیکل Phaser 3.60+:** `scene.add.particles(x, y, 'tex', { speed, lifespan, gravityY, quantity, emitting:false })` + `emitter.explode(n)`.

**لود تنبل موتور:**
```js
const mod = await Promise.race([
  import('./engine/world.js?v=' + V),
  new Promise((_, rej) => setTimeout(() => rej(new Error('engine-timeout')), 6000))
]);
```

## ۶) افزودن بازی جدید — چک‌لیست

1. `kinds/<game>.js` با قرارداد docs/engine.md (windowMsOf/responseOf/previewSteps/welcomeLine/restLine/stimSvg).
2. اگر محرک تازه لازم داری، اول به SHAPES/PALETTE اضافه کن (تک‌منبع)، بعد در world فقط رندر.
3. جوس تخصصی بازی → متد تازه در world.js، نه منطق داخل kind.
4. گیت رفتاری front-gates + یک e2e زنجیره + اجرای دستی مرورگر با اسکرین‌شات.

## ۷) گیت‌های کیفیت قبل از کامیت

- `npm run typecheck` صفر · `npm test` همهٔ آزمون‌ها سبز (گیت رفتاری world.js را هم می‌سنجد)
- `node --check` روی همهٔ دارایی‌های play (شامل phaser.min.js)
- آسمان/شخصیت/محرک در مرورگر واقعی دیده شده؛ فال‌بک با قطع موتور آزموده شده
- باندل بوت سامانهٔ اصلی crm دست‌نخورده (Phaser فقط در ریپوی games)
