# پشتیبان‌گیری و بازیابی داده‌ها — راهنمای عملیات

سه لایهٔ حفاظت از دادهٔ سامانه:

| لایه | ابزار | چه کسی | چه زمانی |
|------|-------|--------|----------|
| ۱. پشتیبان داخل سامانه | منو «پشتیبان‌گیری» (فقط مدیر) | مدیر مرکز | هفتگی + قبل از تغییرهای بزرگ |
| ۱.ب ارسال پشتیبان به بله | همان منو — کارت «ارسال پشتیبان به بله» (m180) | مدیر مرکز | دستی هر وقت لازم بود + پشتیبان خودکار شبانه (اختیاری) |
| ۲. پشتیبان SQL عملیات | `npm run backup:remote` | اپراتور فنی | قبل از هر انتشار/مایگریشن (خودکار در `npm run update`) |
| ۳. Time Travel خود D1 | بازیابی نقطه‌ای ۳۰ روزه | اپراتور فنی | آخرین پناه — همه‌چیز را از تاریخچه برمی‌گرداند |

## لایهٔ ۱ — داخل سامانه (m179)

- مسیر: منوی «مرکز ← پشتیبان‌گیری» — فقط نقش مدیر.
- **دریافت پشتیبان**: یک فایل JSON (`gh-backup`) از همهٔ جدول‌ها. تیک «فایل‌های پیوستی» بایت فایل‌های تمرین/مدارک (`exercise_file_chunks`) را هم اضافه می‌کند — برای پشتیبان هفتگی لازم نیست و حجم را خیلی بالا می‌برد.
- **بازیابی**: فایل را انتخاب کنید ← سامانه خلاصه را نشان می‌دهد (نسخه، زمان، تعداد ردیف‌ها، هم‌خوانی اسکیما) ← گام ۱ فایل اطمینان از وضعیت فعلی می‌دهد ← گام ۲ تایپ عبارت «بازیابی» ← اجرا ← گزارش جدول‌به‌جدول.
- فایل پشتیبان اطلاعات حساس دارد؛ رمزگذاری‌شده یا در حافظهٔ جدا نگه دارید و از بارگذاری در فضای ابری عمومی خودداری کنید.

## لایهٔ ۱.ب — ارسال پشتیبان به آیدی بله (m180)

مکانیک: همان فایل `gh-backup` با متد `sendDocument` ربات بله به مقصدهای انتخابی فرستاده می‌شود — بدون دانلود و جابه‌جایی دستی.

- **مدیریت مقصدها**: آیدی‌های عددی بله (کاربر/گروه/کانال) با نام دلخواه ذخیره می‌شوند (حداکثر ۱۰ مقصد، هرکدام قابل فعال/غیرفعال کردن). مقصدها در جدول `settings` (کلید `backup_destinations`) نگه‌داری می‌شوند.
- **ارسال فوری**: مقصدهای این ارسال را تیک بزنید ← «ارسال فایل پشتیبان به بله». گزارش هر مقصد (موفق/خطا) همان‌جا نمایش داده می‌شود.
- **پشتیبان خودکار شبانه (اختیاری)**: روشن کنید و مقصدهایش را تیک بزنید — هر شب با cron دیجست (۰۴:۰۰ UTC ≈ ۷:۳۰ تهران) بعد از حلقهٔ اعلان‌ها فایل به مقصدهای فعالِ تیک‌خورده فرستاده می‌شود. خاموش = هیچ‌چیز.
- پیش‌نیاز: secret `BALE_BOT_TOKEN` روی worker ست شده باشد (همان ربات اعلان‌ها). اگر ست نباشد، کارت ارسال هشدار می‌دهد و خطای روشن فارسی برمی‌گردد.
- سقف حجم فایل ارسالی: ۴۸ مگابایت. اگر با «فایل‌های پیوستی» از سقف گذشت، خطا می‌گیرید — ارسال سبک (بدون پیوست) را انتخاب کنید.
- رویدادهای `backup.send` / `backup.auto_send` / `backup.delivery_update` در `audit_log` ثبت می‌شوند.
- بازیابی فایل دریافتی از بله: همان مسیر «بازیابی از فایل پشتیبان» — فایل را از بله ذخیره و در پنل بارگذاری کنید.

## لایهٔ ۲ — SQL عملیات (CLI)

```bash
# پشتیبان کامل (اسکیما + داده) — قبل از هر update خودکار هم اجرا می‌شود
npm run backup:remote          # → backups/backup-YYYY-MM-DDTHH-MM-SS.sql

# بازیابی کامل روی پروداکشن (فقط فاجعه/پایگاه تازه — با هماهنگی!)
npx wrangler d1 execute center-system-db --remote --file=backups/<فایل>.sql
```

تفاوت فایل‌ها: پشتیبان داخل سامانه **JSON داده‌محور** است (بازیابی انتخابی/سریع داخل خود اپ)؛ پشتیبان CLI **SQL کامل** است (بازسازی کل اسکیما+داده روی پایگاه تازه).

## لایهٔ ۳ — Time Travel

D1 کلادفلر به‌صورت پیش‌فرض ۳۰ روز تاریخچه نگه می‌دارد. بازیابی نقطه‌ای از داشبورد Cloudflare: **Storage & Databases → D1 → center-system-db → Time Travel → Restore to point in time**. این عملیات کل پایگاه را به لحظهٔ انتخابی برمی‌گرداند (کل جایگزین می‌شود) و محدودیت سهمیهٔ بازگردانی روزانه دارد.

## سناریوهای رایج

| وضعیت | راه‌حل پیشنهادی |
|-------|------------------|
| «اشتباهی چند دانش‌آموز/فرم را پاک کردم» | لایهٔ ۱: بازیابی فایل پشتیبان آخر داخل سامانه |
| «بعد از یک بازیابی چیزها به‌هم ریخت» | فایل اطمینان گام ۱ را برگردانید یا Time Travel |
| «کل پایگاه خراب شد / پایگاه جدید ساختم» | لایهٔ ۲: SQL کامل + `d1 migrations apply` سپس فایل SQL |
| «می‌خواهم به دیروز برگردم» | لایهٔ ۳: Time Travel به لحظهٔ دلخواه |

## نکات فنی (برای توسعه‌دهنده)

- مکانیک کامل بازیابی در `src/application/backup/README.md` توضیح داده شده است.
- سقف حجم فایل بازیابی: ۶۰MB (سرویس + رابط کاربری)؛ سقف ارسال به بله: ۴۸MB (`BACKUP_MAX_SEND_BYTES`).
- رویدادهای `backup.export` / `backup.restore` / `backup.send` / `backup.auto_send` / `backup.delivery_update` در `audit_log` ثبت می‌شوند.
- ارسال فایل: `src/core/notify/bale/documents.ts` (`sendBaleDocument` — multipart به `tapi.bale.ai/bot<token>/sendDocument`)؛ تزریق sender آزمایشی برای تست‌ها از `backupDocumentSender`.
- تست‌ها: `src/application/backup/__tests__/backup.test.ts` (چرخهٔ رفت‌وبرگشت، RBAC، چرخهٔ FK، بازیابی سبک، مقصدها/ارسال/خودکار m180).
