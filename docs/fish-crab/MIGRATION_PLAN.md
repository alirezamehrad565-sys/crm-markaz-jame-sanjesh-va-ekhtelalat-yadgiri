## ۴. قراردادهای مشترک پیش از پیاده‌سازی (قاعدهٔ ۳ مسترپرامپت)

1. **قرارداد ماژول نوع** (ثبت‌شده): `stimSvg/previewSteps + هوک‌های اختیاری` — هر بازی جدید فقط همین + بانک + سنجه؛ هیچ listener/شبکه‌ای در ماژول نوع.
2. **قرارداد ItemView/حذف کلید**: هر فیلد تازه باید از `toItemView`+`stripAnswerKeys` بگذرد؛ گیت نشتی هر نسخه تکرار شود.
3. **قرارداد ثبت**: شواهد ۸ستونه + response_json کامل + idem_key — «دادهٔ خام هرگز دور ریخته نمی‌شود» گیت‌دار.
4. **قرارداد انتشار**: بستهٔ نسخه‌دار تغییرناپذیر؛ آستانه‌ها همیشه `{value, rationale, status}`؛ ارزیابی هرگز مرحله/ستاره/بازخورد نمی‌بیند (C1).
5. **قرارداد کارایی**: هر تغییر باید perf-budget سبز بگذارد؛ ratchet فقط با دلایل مکتوب.
6. **قرارداد جداسازی**: کودک (`/m/:token`) و درمانگر (`#/games`) هرگز یک پوسته نمی‌شوند؛ امتیاز سرگرمی (ستاره) و سنجهٔ شناختی هرگز یکی نمی‌شوند.
