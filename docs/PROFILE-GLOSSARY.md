# واژه‌نامهٔ پروندهٔ دانش‌آموز — طبقه‌بندی واژگانی UI (۱.۲۷.۵۵)

> درخواست کارفرما: هیچ کلمه و عبارتی نباید به گوش کاربر ناآشنا و بی‌معنی بیاید.
> این سند قرارداد واژگان رابط کاربری بخش «پروندهٔ دانش‌آموز» است؛ گیت ماشینی آن در
> `scripts/ui-voice-check.mjs` (توکن‌های ممنوعهٔ ۱.۲۷.۵۵) پین شده و هر رشتهٔ تازه باید همین قواعد را رعایت کند.

## قاعدهٔ نوشتن (برای همهٔ موج‌های بعدی)

1. واژهٔ روزمرهٔ مرکز بر واژهٔ طراحی/ترجمهٔ خام مقدم است («تاریخچه» نه «روایت»، «اصالت سند» نه «مطابقت محتوا»).
2. هر مفهوم فقط یک نام دارد: نامِ تب، نامِ کارت، نامِ دکمه و پیامِ مرتبط باید یکی باشد (اگر تب «تاریخچه» است، عنوان کارت هم «تاریخچهٔ پرونده» است).
3. اصطلاح بالینی فقط برای مخاطب بالینی مجاز است (وکسلر، FSIQ، بازسنجی، نارساخوانی)؛ در متن‌های خانواده/منشی یا tooltipهای عمومی معنی روزمره کنارش می‌آید.
4. جزئیات فنی (SHA-256، سال جلالی، endpoint) هرگز در متن اصلی نمی‌آید؛ حداکثر در tooltip با زبان ساده («کد کنترل»).
5. پیامِ پیش‌نیاز هرگز بن‌بست نیست: همیشه یک اقدام بعدی («رفتن به تفسیر بالینی») دارد.

## الف) واژه‌های اصلاح‌شده در ۱.۲۷.۵۵

| پیش‌تر | پس از اصلاح | چرا |
|---|---|---|
| روایت پرونده | **تاریخچهٔ پرونده** | «روایت» واژهٔ طراحی بود؛ تب هم «تاریخچه» است — دو نام برای یک چیز گیج‌کننده بود |
| خروجی نسخه‌دار (دکمه) | **صدور گزارش قطعی** | «نسخه‌دار» بی‌معنی برای کاربر؛ «قطعی» با «گزارش قطعی» یعنی همان چیزی که روز صدور بود، عوض نمی‌شود |
| نسخهٔ قطعی گزارش (مودال) | **گزارش قطعی — شمارهٔ …** | هم‌خانوادهٔ بالا؛ شماره در عنوان خودش گویاست |
| سررسیده‌گذشته (بج/برگهٔ جلسه) | **عقب‌افتاده** | ترکیب سنگین؛ «پیگیری عقب‌افتاده» روزمره است، «سررسید» به‌عنوان ستون تاریخ می‌ماند |
| مطابقت محتوا: تأیید | **اصالت سند: تأیید** | ترجمهٔ خام hash match؛ «اصالت سند» همان چیزی را می‌گوید که کاربر می‌فهمد: این سند همان است که صادر شد |
| قطعی‌سازی (برچسب تاریخ) | **تاریخ قطعی** | اسم مصدر فنی؛ در UI فعل و صفت ساده |
| SHA-256: … (tooltip) | **کد کنترل: …** | در tooltip با زبان ساده؛ متن اصلی فقط «اصالت سند» |

## ب) واژه‌های تأییدشده — آشنا و می‌مانند

| واژه | کجا | دلیل آشنایی |
|---|---|---|
| تاریخچه، جلسات، تمرین‌ها، ارتباطات، اطلاعات پایه، بازی‌ها | تب‌های پرونده | نام‌های روزمرهٔ سامانه از قبل |
| غربال و ورود، ارزیابی، طرح درمان، دورهٔ درمان، بازسنجی و تصمیم | فصل‌های تاریخچه | واژگان جاری مرکز؛ «طرح درمان» خودش منوی اصلی سامانه است، «بازسنجی» واژهٔ مسیر مداخله |
| ثبت‌های پراکنده | فصل fallback | صادقانه و بی‌ادعای بالینی — وقتی ساخت فصل‌بندی ممکن نیست |
| برگهٔ جلسه، ادامه از جلسهٔ قبل، جلسهٔ گذشتهٔ بی‌گزارش | برگهٔ جلسه | جملهٔ روزمرهٔ کار روزمرهٔ مرکز |
| پیگیری باز / پیگیری عقب‌افتاده / ثبت نتیجه | صف پیگیری | قلم‌به‌قلم با ستون‌های وضعیت followups |
| گزارش‌های خروجی (چیپ آرشیو) | تاریخچه | «خروجی گزارش» جملهٔ جاری مرکز |
| نقطهٔ کلیدی، لحظهٔ کلیدی | ستارهٔ milestone | ساده و بی‌ادعا |
| حاضر / غایب / در انتظار / لغو | سرصفهٔ فصل و جلسات | همان واژگان حضور و غیاب |
| جلسه، تمرین ارسالی، بازخورد تمرین، پیگیری جدید، تصمیم کمیسیون، رویداد | خط خلاصهٔ هر فصل | شمارش‌های ساده با نام واقعی اشیا |

## ج) واژه‌های بالینی — فقط برای مخاطب بالینی، با پشتوانهٔ متن

| واژه | کجا | شرط مجوز |
|---|---|---|
| نیم‌رخ وکسلر — FSIQ … | milestone تاریخچه | فقط رشتهٔ رویداد بالینی؛ درمانگر مخاطب آن است؛ عدد و بند خودش توضیح می‌دهد |
| مسیر مداخله / گزارش دورهٔ مداخله | صدور گزارش | واژهٔ سامانه («طرح درمان» در منو؛ «مسیر مداخله» در تفسیر بالینی) — متن پیش‌نیاز، «جلسات، کارت‌ها و سنجش‌ها» را هم می‌گوید تا بی‌ابهام بماند |
| تفسیر بالینی | نام تب | نام موجود سامانه |

## د) اتصال به گیت

- توکن‌های ممنوعهٔ بخش «الف» در `scripts/ui-voice-check.mjs` پین شده‌اند؛ هر رشتهٔ رندرشوندهٔ تازه که آن‌ها را برگرداند، گیت قرمز می‌شود.
- هر واژهٔ تازهٔ طراحی که موج بعد می‌آورد، باید اول به این سند بیاید (ستون «پس از اصلاح») و بعد در کد — نه برعکس.
