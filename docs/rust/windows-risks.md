# ریسک‌های ویندوز پوستهٔ میز — نقد، پیش‌بینی و اقدام (v1.27.03)

> منبع این سند: گزارش‌های نصاب واقعی کارفرما (v1.27.0 تا v1.27.02) + ایشوهای upstream
> `cloudflare/workerd#4668` و `#7581`. نقدِ معماریِ «یک موتور بومی برای همه» و فهرست
> باگ‌های محتمل آینده با وضعیت هر کدام. این سند با هر تغییر در زنجیرهٔ ویندوز به‌روز شود.

## ۱. درس سه گزارش واقعی — زنجیرهٔ شکست از نصب تا راه‌اندازی

1. **v1.27.0 — «Parse error» capnp**: مسیر `%APPDATA%` با بک‌اسلش خام داخل رشته‌های قالب
   capnp جایگذاری می‌شد (`C:\Users\...` → `\U` = escape نامعتبر). *رفع:* escape + گیت.
2. **v1.27.01 — «access violation 0xc0000005»**: پارس درست بود؛ خود باینری workerd هنگام init
   ترکید (استک هم‌الگوی upstream). *تلاش رفع در v1.27.02:* توزیع redist در نصاب + تشخیص هدفمند.
3. **v1.27.02 — همان کرش، redist هم بی‌اثر**: لاگ Burn کارفرما نشان داد redist سیستمش **۱۴٫۵۲**
   تازه‌تر از نسخهٔ بسته است و ویندوز دانگرید را با `0x80070666` رد می‌کند؛ کرش هم باقی بود.
   نتیجه: کرش upstream workerd با تعویض redist روی این ماشین حل نمی‌شود.
   *رفع ریشه‌ای در v1.27.03:* **workerd از مسیر دسکتاپ حذف شد** — موتور تازه، باندل‌های همان
   ورکرها را درون فرایند Node (سایدکار) اجرا می‌کند؛ shim کامل D1 روی `node:sqlite` همان فایل
   SQLite را باز می‌کند (دیتای کارفرما حفظ است)؛ پوستهٔ Rust سوپروایزر همان است. گیتِ هر دو
   موتور (workerd توسعه + adapter نصاب) در CI با smoke ۲۷بررسی تثبیت شد.

**نقد اصلی (به‌روز):** وابستگی «باینری بومی خارجی برای serving محلی» اشتباه بود — نه به‌خاطر
کیفیت workerd، بلکه به‌خاطر کنترل‌ناپذیری رفتارش روی ویندوزهای متنوع. معماری تازه فقط دو وابستگی
بومی دارد: WebView2 (سیستمی) و node.exe (runtime بالغ با سال‌ها پایداری ویندوزی). منطق اپ
(Hono + D1) عین همان باندل‌های گیت‌شده است — یک منبع حقیقت برای سرور مرکزی و دسکتاپ.

## ۳. نقشهٔ راه پیشنهادی (به‌ترتیب بازده)

1. **تأیید v1.27.03 روی ماشین کارفرما** — انتظار: بوت موفق؛ دیتای موجود حفظ می‌شود.
2. **امضای کد** — ساکت‌کردن SmartScreen/AV (ریسک ۴).
3. **پروب خودکار پیش از بوت** — اگر spawn node شکست خورد، پیام در ~۱ ثانیه به‌جای ۳۰ ثانیه.
4. **Runtime جایگزین صفر وابستگی بومی** — اگر روزی node هم مشکل ساخت: axum + rusqlite در همان
   پوستهٔ Rust (بازنویسی API) — سرمایهٔ بزرگ؛ فقط در صورت شکست واقعی گام ۱.
5. **چرخش لاگ سمت Rust + تکی‌نمونه** — بهداشت جزئی (ریسک‌های ۹ و ۱۰).

## ۴. قرارداد برای تغییرهای آیندهٔ زنجیرهٔ ویندوز

- کانفیگ موتور فقط JSON/CLI — هیچ قالب متنی با escape دستی.
- هر دارایی تازهٔ نصاب = دانلود/کپی در `build-installer-runtime` + هش در مانیفست + `--check`.
- هر پیام خطای تازه = متن فارسیِ کاربرپسند در `lib.rs` + ارجاع به `dataDir/engine.log`.
- هر تغییر موتور = دوهاته بودن engine-smoke (workerd + adapter) در CI و سبزی desktop-check.
- گیت‌های مربوطه: `desktop-check` بخش ⑦ (رانتایم)، ⑧ (adapter)، ⑨ (نصاب node) باید سبز بمانند.
