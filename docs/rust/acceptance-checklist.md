# چک‌لیست پذیرش کارفرما — خط rust (شش فاز)

> سند امضایی: پس از اجرای واقعی هر گیت، ستون «وضعیت» توسط کارفرما تکمیل و امضا می‌شود.
> ستون «شواهد موجود» گزارش صادقانهٔ سازنده تا کامیت `rust-f5` است — هیچ گیتِ اجرا‌نشده‌ای تیک نمی‌خورد.
> مرجع: `docs/rust/design.md`، `docs/rust/phases.md`، `docs/rust/installer.md`. قاعدهٔ خط: بدون دیپلوی وب، نسخهٔ یکتا = `APP_VERSION`.

## ۷) باقی‌مانده‌های محیط توسعه / CI (شایطه‌های هنوز اجرا‌نشده)

این فهرست دقیقاً کارهایی است که در سندباکس فعلی (بدون toolchain Rust و بدون ویندوز) ممکن نبود و در محیط توسعه/CI باید اجرا شود:

| # | باقی‌مانده | دستور/محل | وابسته به |
|---|---|---|---|
| ۱ | کامپایل cargo پوستهٔ دسکتاپ | `cargo check` سپس `cargo build` در `desktop/src-tauri/` روی ویندوز/CI (Rust stable + MSVC) | runner ویندوز |
| ۲ | ساخت NSIS روی ویندوز | `npx @tauri-apps/cli@^2 build` پس از `npm ci && npm run build:client` → `target/release/bundle/nsis/*-setup.exe` | ردیف ۱ |
| ۳ | تکمیل پک با نصاب | `npm run usb:pack` روی همان ماشین (اسکریپت Setup.exe را خودکار کپی و سربرگ PE را اعتبارسنجی می‌کند) | ردیف ۲ |
| ۴ | نصب تمیز ویندوز ۱۰/۱۱ روی VM | نصب Setup.exe بدون ادمین → اجرای آفلاین → حذف/نصب مجدد با حفظ `data` | ردیف ۲ |
| ۵ | آزمون autorun روی ویندوز واقعی | AutoPlay روشن/خاموش دو سناریو؛ مسیر دستی Setup.exe | ردیف ۴ |
| ۶ | گواهی امضای کد (پیشنهاد کارفرما) | پر کردن placeholderهای `bundle.windows` در tauri.conf.json (installer.md §۳-۳) — بدون آن: هشدار SmartScreen مستند | خرید/تصمیم کارفرما |
| ۷ | تصمیم WebView2 کاملاً آفلاین | `webview2InstallMode: "offlineInstaller"` (+~۱۲۰MB) یا پیش‌فرض downloadBootstrapper | حکم کارفرما |
| ۸ | سایدکار workerd در نصاب (فاز ۲+) | دانلود pinned-version در CI + `externalBin` + ثبت هش | فاز ۲ |
| ۹ | امضای این چک‌لیست | جدول امضای پایین — پس از سبز شدن همهٔ ردیف‌های فازها | همهٔ ردیف‌ها |
