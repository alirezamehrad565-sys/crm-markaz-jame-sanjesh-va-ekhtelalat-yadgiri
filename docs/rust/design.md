# طراحی اپ دسکتاپ مرکز جامع — نسخهٔ میز با موتور محلی و سینک ترکیبی (خط rust)

> حکم کارفرما: دیپلوی وب انجام نمی‌شود؛ شاخهٔ `rust` خط تولید اپ دسکتاپ است. هدف: **نرم‌افزار دسکتاپ + اتوران نصب + توتوریال اولیه + سیستم ترکیبی با ورکر Cloudflare**. این سند طراحی است؛ فازبندی و اقدامات در `docs/rust/phases.md`.

## ۱. هدف و دامنه

سامانهٔ مرکز جامع امروز یک وب‌اپ Cloudflare Worker است (Hono + D1 + ۲۲۸۳ آزمون). هدف این خط، همان سامانه به‌عنوان **نرم‌افزار میز (دسکتاپ ویندوز)** است که:

- **کاملاً آفلاین** کار کند (مرکز بدون اینترنت هم بتواند ثبت/گزارش/بازی کند)؛
- با یک **اتوران نصب** توزیع شود (setup.exe فارسی + پک پورتابل USB با autorun)؛
- اجرای نخست، **توتوریال نقش‌محور** داشته باشد (مدیر/منشی/درمانگر)؛
- وقتی اینترنت هست، با **ورکر Cloudflare سینک ترکیبی** کند (الگوی نود↔کنترل‌پلینِ موجود).

اصل بنیادین — **یک منبع، دو میزبان**: هیچ منطق محصولی بازنوشته نمی‌شود. همان بک‌اند ورکر (باندل‌ها) روی یک runtime محلی اجرا می‌شود و همان کلاینت (`public/`) در پنجرهٔ دسکتاپ بالا می‌آید. پارتی آزمون (۲۲۸۳ e2e) حفظ می‌شود.

## ۲. معماری چهارلایه

```
┌─ پوستهٔ دسکتاپ (Tauri 2 — Rust) ─────────────────────────────┐
│  پنجره ← WebView2 ← http://127.0.0.1:8787                    │
│  فرمان‌های بومی: نسخه/سلامت، بازکردن پوشهٔ داده، بعداً چاپ     │
├─ موتور محلی (سایدکار) ───────────────────────────────────────┤
│  workerd ← worker/bundle.js (بک‌اند کامل)                    │
│         ← worker/games-bundle.js (ماژول بازی‌ها — ۱.۲۵.۷۵)   │
│  D1 محلی = فایل SQLite در %APPDATA%/center-desktop/data      │
│  assets محلی = build:client خروجی (همان CSP/کوکی/سرویس‌ورکر) │
├─ کلاینت (بدون تغییر) ────────────────────────────────────────┤
│  همان public/ با ?v= هم‌گام — کوکی احراز همان‌محلی می‌ماند    │
├─ سینک ترکیبی (الگوی نود CP) ─────────────────────────────────┤
│  pull: اعلان/کتابخانهٔ شبکه/بسته‌های بازی/تغییرات ساختاری     │
│  push: گزارش تجمیعی، خطاهای مرورگر، وضعیت سلامت              │
│  قاعده: دادهٔ بالینی فقط با رضایت صریح کارفرما از میز خارج   │
└──────────────────────────────────────────────────────────────┘
```

**چرا پنجره `http://127.0.0.1:8787` را بار می‌کند و نه فایل‌های استاتیک؟** کلاینت فرض «هم‌ریشته بودن API» را دارد (کوکی، fetch نسبی، سرویس‌ورکر، CSP). با میزبانیِ موتور محلی روی loopback، دقیقاً همان قرارداد تولید بدون هیچ انشعابی برقرار است. فاز ۱ فقط شل است (استاتیک)؛ از فاز ۲ پنجره به loopback سوییچ می‌کند.

## ۳. تصمیم‌های کلیدی (ADR فشرده)

| # | تصمیم | گزینه‌های ردشده | دلیل |
|---|---|---|---|
| D1 | موتور محلی = **سایدکار workerd** با همان باندل‌های ورکر | پورت فوری Rust از Hono/D1 | پارتی رفتاری ۲۲۸۳ آزمون و دو باندل منجمد حفظ می‌شود؛ پورت Rust ماژول‌به‌ماژول در فاز ۶ ارزیابی می‌شود (شروع از games که از ۱.۲۵.۷۵ مرزش مستقل است) |
| D2 | پوسته = **Tauri 2** | Electron | حجم/حافظهٔ بسیار کمتر، WebView2 سیستم‌عامل، زنجیرهٔ اصلی Rust = همان هدف «نرم‌افزار rust» |
| D3 | D1 محلی = فایل SQLite با امولیشن D1 workerd | ریموت D1 در ابر (فقط-SaaS) | آفلاین بودن شرط حکم است؛ فایل SQLite همچنین پشتیبان‌گیری/کپی ساده دارد |
| D4 | احراز محلی = همان `@core/auth` + `runtime-secret` با `AUTH_SECRET` نصب‌محور | سیستم جداگانهٔ لوکال | توکن/نشست همان قرارداد؛ آزمون‌ها بدون تغییر؛ گیم‌ورکر مستقل (۱.۲۵.۷۵) روی همان secret کار می‌کند |
| D5 | سینک = **همان پاکت نود CP** (m1.5/cp-sync/cp-report/cp-content — node_code/node_key، idempotent (node_code,id)، مُهر تلاش) | پروتکل سینک تازه | دوسمت پروتکل از قبل آزمون‌خورده‌اند؛ دسکتاپ فقط «نودی دیگر» با node_code خودش است |
| D6 | توزیع = **NSIS نصاب + پک پورتابل USB** | فقط نصاب / MSI | مرکزها اغلب بدون اینترنت و با USB نصب می‌کنند؛ autorun خواستهٔ صریح کارفرماست |
| D7 | نسخه‌گذاری دسکتاپ = نسخهٔ منبع (`APP_VERSION`) + نشان فاز | نسخهٔ مستقل دسکتاپ | یک شماره، یک حقیقت؛ گیت `desktop:check` ناهم‌گامی را می‌گیرد |

## ۴. موتور محلی (جزئیات فاز ۲)

- **اجرا**: Tauri هنگام شروع `workerd` را به‌صورت پروسهٔ فرزند با کانفیگ تولیدشده بالا می‌آورد: بایند فقط روی `127.0.0.1`، پورت آزاد از محدودهٔ ثابت (۸۷۸۷ پیش‌فرض، اگر اشغال بود پورت آزاد بعدی و پاس‌دادن به پنجره)، خاموشی تمیز با خروج اپ.
- **داده**: `data.sqlite` فایل D1 (مایگریشن‌ها ۱ تا ۱۱۱ با همان `migrations/` اعمال می‌شوند — گیت migrations-doc همین today هم پوشش می‌دهد) + `seed-demo` برای توتوریال.
- **باینری workerd** (~۳۰MB per-platform) در بستهٔ نصاب قرار می‌گیرد؛ در CI دانلود pinned-version و هش آن ثبت می‌شود (هم‌الگوی انضباط آرتیفکت-منجمد).
- **سلامت**: `GET /health` موتور محلی هر ۵ ثانیه از Rust پینگ می‌شود؛ قطع → پنجرهٔ «موتور محلی در حال راه‌اندازی…» با دکمهٔ تلاش دوباره؛ هیچ مسیری ساکت نمی‌شکند (الگوی استقلال §۳-۱۱ سند ارتقا).

## ۵. سینک ترکیبی (جزئیات فاز ۴)

- **هویت نود**: `node_code = DESKTOP:<install-id>` + `node_key` در اولین راه‌اندازی؛ ثبت دستی در اپ ابری (فقط-مدیر) — همان اعتماد پیوند دستی CP↔نود.
- **حالت‌ها**: `آفلاین` (بدون env سینک — همه‌چیز محلی)، `ترکیبی` (pull دوره‌ای فرصت‌طلب بعد از هر ورود موفق + push شبانه؛ گیت‌های ۱۵دقیقه/۲۴ساعت همان نویز-سپرهای موجود)، `فقط-ابری` (حالت today تولید — بدون تغییر).
- **جهت داده**: پیش‌فرض pull: اعلان‌ها، کتابخانهٔ شبکه، بسته‌های بازی منتشرشده، تنظیمات مرکزِ مزاحم‌نیست. push: گزارش تجمیعی استفاده، خطاهای مرورگر، پینگ سلامت. **انتقال تاریخچهٔ بالینی (مراجعان/جلسات/تجویزها) ممنوع مگر حکم آتی کارفرما** — این قاعده در کد سینک با فهرست سفید دامنه‌ها اعمال می‌شود نه فقط در سند.
- **تعارض**: دادهٔ pull فقط-خواندنی محلی (پوشش با منبع ابر)؛ دادهٔ محلی هرگز از ابر بازنویسی نمی‌شود → تعارض ساختاری منتفی است؛ اگر روزی دوطرفه شد: LWW بر `updated_at` + audit رویداد تعارض.

## ۶. اتوران نصب و توزیع (طراحی فاز ۵)

- **نصاب NSIS** (خروجی Tauri bundler): زبان فارسی پیش‌فرض، نصب per-user (بدون نیاز ادمین)، میان‌بر دسکتاپ/استارت، آیکن اختصاصی، حذف تمیز با نگه‌داشتن داده.
- **پک پورتابل USB**: `autorun.inf` (آیکن + اجرای Setup.exe) + `Setup.exe` + پوشهٔ `app/` (باینری‌ها) + `README-نصب.txt` فارسی؛ برای سناریوی «برگشت به نصب قدیمی»، نصاب نسخهٔ قبلی را نگه نمی‌دارد — پشتیبان داده جدا از برنامه است (`data/` مستقل از `app/`).
- **امضا و بروزرسانی**: امضای کد (وقتی گواهی تهیه شد — placeholder مستند)؛ بروزرسانی = نصب‌کنندهٔ جدید روی همان data؛ شماره نسخه از `APP_VERSION`.
- **پیش‌نیاز**: WebView2 (روی ویندوز ۱۰/۱۱ تقریباً همیشه حاضر؛ نصاب evergreen bootstrapper در بسته).

## ۷. توتوریال اولیه (طراحی فاز ۳)

- **چه کسی، چه می‌بیند**: ورود نخست پس از seed دیتای نمایشی → تور نقش‌محور: مدیر (تنظیمات/پشتیبان/کاربران/پنل سلامت)، منشی (نوبت/لیست انتظار/تابلوی امروز)، درمانگر (تجویز بازی/مأموریت‌ها/گزارش). ۸–۱۲ گام، قابل‌ردشدن در هر لحظه، هرگز مسیر را قفل نمی‌کند.
- **پیاده‌سازی**: ماژول `tutorial` در کلاینت (دادهٔ گام‌ها JSON + overlay + state در localStorage `tutorial_state`)؛ تکرار از تنظیمات؛ در نسخهٔ وب همین ماژول خاموش می‌ماند (FEATURES) تا رفتار تولید دست‌نخورده بماند.
- **دیتای نمایشی**: `seed-demo` مخصوص میز (مرکز «نمونه»، سه کاربر نقشی، چند مرجع/تجویز/بستهٔ بازی) — دکمهٔ «پاک‌کردن دادهٔ نمایشی» در تنظیمات.

## ۸. امنیت

- بایند فقط loopback؛ هیچ پورتی روی شبکهٔ محلی باز نیست.
- داده در `%APPDATA%` (خارج از پوشهٔ برنامه)؛ فاز ۵: رمزگذاری در حال سکون (SQLCipher یا DPAPI کاربر ویندوز) + پشتیبان رمزشدهٔ اختیاری.
- ممیزی همان `audit_log` محلی؛ لاگ خطا محلی می‌ماند مگر push خطاهای مرورگر فعال باشد.
- سینک فقط https به ورکر رسمی با node_key؛ هرگز دادهٔ بالینی (بند ۵).

## ۹. ریسک‌ها و دفع

| ریسک | دفع |
|---|---|
| باینری workerd حجم بسته را بالا می‌برد | پذیرش: ~۳۵MB نصاب؛ ارزیابی پورت Rust تدریجی (فاز ۶) |
| WebView2 نبود روی ویندوزهای خیلی قدیمی | bootstrapper evergreen در نصاب + سند پیش‌نیاز |
| سقف پلن Free ابر برای سینک | سینک تجمیعی/فرصت‌طلب همان الگوی مُهر تلاش؛ سقف‌ها در فاز ۴ اندازه‌گیری می‌شود |
| نبود toolchain Rust در محیط جاری | فاز ۱ گیت ساختاری دارد؛ کامپایل/NSIS در فاز ۲ به‌بعد در محیط توسعه/CI با Rust stable |
| رانش باندل‌ها با منبع | گیت موجود artifact-frozen + بازسازی از منبع؛ `desktop:check` ناهم‌گامی نسخهٔ دسکتاپ را می‌گیرد |

## ۱۰. گیت‌های کیفیت خط rust

`desktop:check` (ساختار/نسخه/آیکن/کانفیگ) از فاز ۱؛ `engine-smoke` (موتور محلی روی D1 موقت) از فاز ۲؛ `tutorial` e2e از فاز ۳؛ `sync` آزمون پاکت از فاز ۴؛ نصب تمیز ویندوز از فاز ۵؛ ممیزی نهایی پذیرش در فاز ۶. گیت‌های وب موجود (tsc/vitest/build/frozen/csp/migrations) در هر کامیتِ این خط که src/ را دست می‌زند هم اجرا می‌شوند.
