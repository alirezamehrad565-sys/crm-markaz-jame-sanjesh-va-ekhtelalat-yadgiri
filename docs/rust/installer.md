# سند عملیات نصب و توزیع — نسخهٔ میز (خط rust، فاز ۵)

> مکمل `docs/rust/design.md` §۶ و `docs/rust/phases.md` فاز ۵. مخاطب: مسئول فنی مرکز و CI.
> راهنمای کاربر نهایی: `desktop/installer/README-نصب.txt` (همراه پک USB توزیع می‌شود).
> قاعدهٔ خط: **بدون دیپلوی وب، بدون بامپ ورژن** — نسخهٔ همهٔ اجزا = `APP_VERSION` منبع (`src/core/version.ts`).

## ۱. دو خروجی فاز ۵

| خروجی | سازنده | محل |
|---|---|---|
| نصاب NSIS (`Setup.exe`) | Tauri bundler روی **ویندوز/CI با Rust toolchain** | `desktop/src-tauri/target/release/bundle/nsis/*-setup.exe` |
| پک توزیع USB | `npm run usb:pack` (هر جا Node هست) | `dist/usb-pack/` (گیت‌ignore شده) |

در این محیط توسعه toolchain Rust نیست؛ پک با چیدمان کامل و **بدون** `Setup.exe` ساخته می‌شود (هشدار صادقانه در گزارش اسکریپت) و پس از نخستین بیلد CI، همان دستور `npm run usb:pack` پک را کامل می‌کند — اسکریپت نصاب را اگر موجود بود خودکار کپی می‌کند.

## ۲. چیدمان استاندارد پک USB

```
USB/
├─ autorun.inf        # [autorun] open=Setup.exe · icon=Setup.exe,0 · label=مرکز جامع — نسخهٔ میز · action=نصب نسخهٔ میز
├─ Setup.exe          # نصاب NSIS — از خروجی CI (اگر هنوز بیلد نشده: غایب + هشدار اسکریپت)
├─ VERSION.txt        # شمارهٔ نسخه از APP_VERSION + تاریخ شمسی ساخت پک
├─ README-نصب.txt     # راهنمای کامل فارسی کاربر نهایی
└─ app/               # (آینده — فاز ۲ به بعد) باینری‌های موتور محلی از CI؛ الان ساخته نمی‌شود
```

- `autorun.inf` در مخزن UTF-8 است؛ هنگام مونتاژ، اسکریپت آن را با **CRLF و کدگذاری UTF-16 LE با BOM** در پک می‌نویسد — قالبی که ویندوز ۱۰/۱۱ برچسب و متن اجرای خودکار فارسیِ آن را درست نشان می‌دهد. (`open` و `icon` محدود به ASCII هستند و در هر حالت کار می‌کنند؛ اگر روزی دستگاه بسیار قدیمی برچسب را خراب نشان داد، فایل را در Notepad با ANSI بازذخیره کنید — عملکرد autorun تغییر نمی‌کند.)
- `README-نصب.txt` و `VERSION.txt` با BOM و CRLF نوشته می‌شوند تا در Notepad همهٔ ویندوزهای ۱۰/۱۱ بی‌ابهام باشد.
- اجرای خودکار در ویندوز ۷ به بعد «پرسش» است نه اجرای بی‌پرسش؛ اگر AutoPlay دستگاه خاموش باشد، کاربر `Setup.exe` را دستی اجرا می‌کند (بخش ۶-۳ راهنما).
- قالب USB: FAT32 توصیه می‌شود (سازگاری وسیع)؛ exFAT/NTFS نیز autorun را می‌خوانند.

## ۳. ساخت نصاب در CI (Tauri bundler — NSIS فارسی)

### ۳-۱) محیط موردنیاز

- Runner **ویندوز** (windows-latest) با Rust stable (`rustup default stable`) و Node 20+؛
- `npm ci` سپس `npm run build:client` — چون `frontendDist = ../public` است و bundler محتوای کلاینت را داخل نصاب می‌گذارد؛
- Tauri CLI (پیشنهاد CI): `npx @tauri-apps/cli@^2 build` از ریشهٔ مخزن — کانفیگ از `desktop/src-tauri/tauri.conf.json` خوانده می‌شود. (کامپایل Rust نیازمند MSVC Build Tools است که در windows-latest حاضر است.)

### ۳-۲) چه خروجی‌ای و با چه ویژگی‌هایی

کانفیگ NSIS از فاز ۱ (قفل‌شده با گیت `desktop:check`):

| تنظیم | مقدار | اثر |
|---|---|---|
| `bundle.targets` | `["nsis"]` | خروجی: `.../bundle/nsis/<نام‌محصول>_<نسخه>_x64-setup.exe` |
| `bundle.windows.nsis.installMode` | `currentUser` | نصب per-user در `%LOCALAPPDATA%\Programs` — بدون رمز ادمین |
| `bundle.windows.nsis.languages` | `["Persian","English"]` | نصاب دوزبانه، فارسی پیش‌فرض طراحی |
| `bundle.icon` | `icons/icon.ico` | آیکن نصاب و میان‌برها |
| `productName` | `مرکز جامع — نسخهٔ میز` | نام پوشه/میان‌بر/برنامه در Apps |

حذف تمیز با نگه‌داشتن داده: uninstaller فقط پوشهٔ برنامه و میان‌برها را پاک می‌کند؛ داده در `%APPDATA%\center-desktop\data` (بیرون پوشهٔ برنامه) باقی می‌ماند — رفتار مستند در بخش ۸ راهنمای نصب.

**WebView2**: پیش‌فرض Tauri «downloadBootstrapper» است — اگر WebView2 روی دستگاه غایب باشد، در نخستین نصب یک بار دانلود انجام می‌شود؛ روی ویندوز ۱۰/۱۱ به‌روز تقریباً همیشه از قبل حاضر است. برای بستهٔ کاملاً آفلاین حتی در دستگاه‌های خیلی قدیمی، در CI می‌توان `bundle.windows.webview2InstallMode: "offlineInstaller"` را فعال کرد (+~۱۲۰MB به حجم نصاب) — تصمیم حجم/پوشش با کارفرما (بخش ۷).

**سایدکار موتور محلی (فاز ۲ به بعد)**: باینری `workerd` به‌صورت `externalBin` به bundle اضافه می‌شود؛ در CI نسخهٔ پین‌شده دانلود و هش آن در گزارش ثبت می‌شود (هم‌الگوی انضباط آرتیفکت-منجمد؛ design.md §۴).

### ۳-۳) امضای کد — placeholder مستند (فعال نیست)

تا تهیهٔ گواهی، نصاب **بدون امضا** است و SmartScreen پیام «اجرای به هر حال» می‌دهد (بخش ۶-۲ راهنمای نصب). وقتی گواهی (OV یا Azure Trusted Signing) تهیه شد، در `desktop/src-tauri/tauri.conf.json` این کلیدها پر می‌شوند:

```json
"bundle": { "windows": {
  "certificateThumbprint": "<اثر انگشت گواهی>",
  "digestAlgorithm": "sha256",
  "timestampUrl": "http://timestamp.digicert.com"
} }
```

این جای‌گذاری به‌عنوان placeholder مستند است؛ تا حکم کارفرما هیچ مقدار واقعی‌ای در مخزن نمی‌نشیند و گواهی به مخزن کامیت نمی‌شود (env/secret CI).

## ۴. مونتاژ پک USB — `usb:pack`

```bash
npm run usb:pack      # node scripts/build-usb-pack.mjs
```

رفتار اسکریپت (idempotent — پاک‌سازی و بازسازی کامل `dist/usb-pack`، خروجی هم‌روز تکرارپذیر):

1. نسخه از `APP_VERSION` (یک شماره، یک حقیقت — D7) و تاریخ شمسیِ امروز (ساعت تهران) خوانده می‌شود؛
2. `autorun.inf` + `README-نصب.txt` از `desktop/installer/` با کدگذاری ویندوزی کپی می‌شوند؛
3. `VERSION.txt` ساخته می‌شود؛
4. `Setup.exe` از `desktop/src-tauri/target/release/bundle/nsis/` کپی می‌شود **اگر موجود بود**؛ وگرنه ردِ صادقانه و ادامه؛
5. اعتبارسنجی ساختاری: فایل‌های الزامی و غیرخالی، نام‌های مجاز ریشه، چهار سطر الزامی autorun، هم‌گامی VERSION با APP_VERSION، سرفصل‌های راهنما، سربرگ PE (`MZ`) نصاب؛
6. گزارش فارسی + کد خروج (خطا = ۱، هشدار = ادامهٔ سبز).

### گردش‌کار کامل پس از بیلد CI

```bash
# روی runner ویندوز (یا هر ماشین ویندوزی با Rust):
npm ci && npm run build:client && npm run desktop:check
npx @tauri-apps/cli@^2 build          # → target/release/bundle/nsis/*-setup.exe
npm run usb:pack                      # → dist/usb-pack/ با Setup.exe کامل
# سپس محتوای dist/usb-pack را روی ریشهٔ USB کپی کنید (نه داخل پوشه).
```

اگر فقط آرتیفکت `Setup.exe` را از CI گرفته‌اید، آن را در `desktop/src-tauri/target/release/bundle/nsis/` بگذارید و `npm run usb:pack` را روی هر ماشینی با Node اجرا کنید.

## ۵. چرخهٔ نصب / بروزرسانی / حذف

| چرخه | عمل | اثر بر داده |
|---|---|---|
| نصب نخست | autorun یا `Setup.exe` دستی → نصاب فارسی per-user | پوشهٔ داده در اولین اجرا ساخته می‌شود؛ مایگریشن‌ها و seed-demo در فازهای ۲/۳ خودکار اعمال می‌شوند |
| بروزرسانی | برنامه را ببندید → `Setup.exe` نسخهٔ جدید روی همان محل | **داده دست‌نخورده** — پوشهٔ `data` مستقل از برنامه است؛ پیش از بروزرسانی پشتیبان بگیرید (بخش ۶) |
| حذف | Apps ویندوز یا `unist.exe` پوشهٔ نصب | برنامه و میان‌برها پاک می‌شوند؛ `data` باقی می‌ماند؛ پاک‌سازی نهایی دستی و پس از پشتیبان |
| بازگشت به نصب قدیمی | نصب نسخهٔ قبلی روی همان محل | نصاب نسخهٔ قبلی نگه داشته نمی‌شود؛ پشتیبان `data` جدا از برنامه است — بازگردانی پشتیبان به‌جای «برگشت نصاب» |

پشتیبان‌گیری: برنامه بسته ← کپی کل `%APPDATA%\center-desktop\data` به محل امن با نام تاریخ‌دار (مثال در بخش ۷ راهنما). بازیابی = برگرداندن محتوای پشتیبان جای پوشهٔ `data`.

## ۷. محدودیت‌های کنونی (صادقانه) و باقی‌مانده‌های CI

- در این محیط Rust toolchain نیست → کامپایل cargo و بیلد NSIS هنوز اجرا نشده؛ `Setup.exe` فعلاً در پک نیست (هشدار صادقانهٔ اسکریپت — چیدمان معتبر است).
- autorun فقط ساختاراً اعتبارسنجی شده (محتوا/کدگذاری)؛ آزمون اجرای خودکار روی ویندوز واقعی در گیت «نصب تمیز ویندوز» انجام می‌شود.
- فهرست دقیق کارهای محیط توسعه/CI در `docs/rust/acceptance-checklist.md` §۷ آمده است.
