# بنچمارک کیفیت کد و کمپلکسیتی — ۱.۲۷.۴۴

سؤال کارفرما: «چون AI همه‌چیز را از پایه می‌سازد و به‌جای Tailwind/React همه را خودش می‌نویسد، کد خیلی کمپلکس و ناخوانا نشده؟»

این سند با **عدد** جواب می‌دهد، نه با سلیقه. ابزار سنجش تکرارشدنی و بدون وابستگی خارجی است: `scripts/complexity-bench.mjs` — و از همین نسخه، بخشی از گیت‌های انتشار است تا کد بدترشده quietly قبول نشود.

## ۱) متدولوژی

- هدف اسکن: کد اجرایی `src/` و `public/assets/js/` — بدون `__tests__`، بدون باندل‌های مینیفای‌شدهٔ تولیدی (`worker/*.js` خروجی esbuild است و «سورس» نیست).
- سنجه‌ها: LOC اجرایی، طول تابع (P50/P90/P99/max)، کمپلکسیت تقریبی (شمار تصمیم‌ها: if/for/while/case/catch/&&/||/ternary)، عمق تودرتویی، تکرار بلوکی بین‌فایلی (پنجرهٔ ۸خطی نرمال‌شده)، سهم دو سبک UI (DOM کمکی `el()` در برابر HTML رشته‌ای).
- رِچت: `--baseline` عدد روز را ذخیره می‌کند و `--gate` فقط «بدترشدن» را می‌گیرد (LOC کل +۲٪، فایل تازهٔ ≥۶۰۰LOC، توابع ≥۸۰خطِ تازه، تکرار +۱۰٪). بهترشدن همیشه آزاد است.

## ۳) تشخیص واقعی — کمپلکسیت کجاست؟

سه یافتهٔ اصلی:

1. **مشکل «فریم‌ورک‌نداشتن» نیست.** اگر AI همه‌چیز را بی‌الگو از پایه می‌ساخت، تکرار بلوکی بالا می‌آمد (پروژه‌های مشکل‌دار معمولاً ۱۵–۳۰٪) و P50 تابع بزرگ می‌شد. ما ۲.۹٪ تکرار و P50=۷ داریم — یعنی یک کیت مشترک (`ui.js`، `format.js`، الگوی سرویس/مسیر) واقعاً استفاده می‌شود و توابع کوچک نوشته می‌شوند.
2. **مشکل واقعی: فانکشن‌فکتوری‌های غول.** الگوی معماری این مخزن «سرویس = یک factory بزرگ» است و هفت فایل از این الگو خارج شده‌اند:

(کامنت‌نویسی و سبک متن، طبق قرارداد `docs/CODE-STYLE.md`، از این سند جدا است.)

## ۴) پاسخ به فرضیهٔ React/Tailwind

**جابه‌جایی به React/Tailwind مشکلِ اندازه‌گیری‌شده را حل نمی‌کند و هزینهٔ بالایی دارد.** استدلال عددی و معماری:

1. داغ‌ترین نقاط (جدول §۳) **منطق بک‌اند و کلاینت سنگین است، نه UI** — React فقط لایهٔ نمایش را می‌سازد؛ `createExerciseBankService` با React کوتاه نمی‌شود. فرضیه از جنس «UI کمپلکس است» بود، اما عدد می‌گوید UI با کیت مشترک از قبل منظم‌ترین بخش است (۶۹ نما با `el()`).
2. این معماری عمداً **صفر-وابستگی در زمان اجرا** است (قرارداد پین‌شدهٔ مخزن): ورکر Cloudflare + موتور خودمیزبان + سندباکس CSP + RTL فارسی. React یعنی +۴۵KB gz به باندل، hydration روی صفحات رشته‌محورِ سرو شده از سرور، و بازنویسی ۶۹ نما با ۳٬۰۳۲ آزمون پین‌شده — ریسک رگرسیون بالا در برابر صفر سود سنجه‌ای.
3. Tailwind هم یک زنجیرهٔ build و کلاس‌های ابزاری می‌آورد که با دیزاین‌سیستم موجود (توکن‌های `--sp-*`، کلاس‌های معنایی `.card/.btn/.badge` در `panel.css`) جاگزینی دوگانه می‌سازد؛ نتیجه دو سیستم استایل موازی — دقیقاً همان «ناخوانایی» که می‌خواهیم حذف کنیم.
4. آنچه واقعاً کمپلکسیت را کم می‌کند، در §۵ آمده: شکستن فانکشن‌فکتوری‌ها به ماژول‌های زیردامنه، بودجهٔ اندازه با گیت رِچت، و قرارداد صریح برای کد AI-ساخت.

جمع‌بندی: **نه بازنویسی فریم‌ورکی؛ بازآرایی ماژولی هدفمند + گیت رِچت.** اگر روزی UI پیچیدگی تعاملیِ SPA-سنگین (دریگ‌اند‌دراپ پیچیده، گرید ویرایشی) گرفت، ارزیابی React فقط برای «یک نما» در آن زمان معنا دارد — نه کل سیستم.

## ۵) نقشهٔ راه عملی

### ۵.۱) همین نسخه پیاده شد

- **ابزار بنچمارک پایدار**: `node scripts/complexity-bench.mjs` (گزارش) · `--baseline` (ثبت) · `--gate` (رِچت) — و اسکریپت‌های npm: `npm run bench:complexity` / `npm run bench:gate`.
- **گیت رِچت در زنجیرهٔ انتشار**: LOC کل، فایل ≥۶۰۰LOC تازه، تابع ≥۸۰خط تازه و تکرار بلوکی — هیچ‌کدام حق بدترشدن بی‌اجازه ندارند؛ از این به بعد هر PR/کامیت باید یا زیر آستانه بماند یا بیس‌لاین را آگاهانه با دلیل به‌روزرسانی کند.

### ۵.۲) بودجه‌های نوشتن (برای کد AI-ساخت هم لحظهٔ تولید اعمال شود)

- فایل تازه ≤ ۶۰۰ LOC؛ تابع تازه ≤ ۸۰ خط؛ تودرتویی ≤ ۴.
- نما: یک فایل = یک نما؛ زیربخش‌های >۱۵۰ خط به تابع render مجزا (`xxxRowView`, `xxxFilters`) در همان فایل.
- سرویس: factory را با تزریق deps نگه دارید ولی هر زیردامنه (مثلاً در بانک تمرین: بسته‌ها/فایل‌ها/برچسب‌ها/لینک دانلود) در ماژول جدا تعریف و فقط compose شود.
- متن‌های چندواریانت فارسی (لیبل بات) فقط در فایل‌های دادهٔ متمرکز (`templates.ts` و امثالش) — هیچ منطق کنار داده نچسبد.
- کامنت‌ها طبق `docs/CODE-STYLE.md` (فارسی محاوره‌ای، «چرا» نه «چه»).

### ۵.۳) ترتیب بازآرایی پیشنهادی (هر نسخه یکی، با کل گیت‌ها سبز)

1. `views/health-panel.js::serverAddressView` (۱٬۶۰۰ خط، تودرتویی ۱۱) — به زیرنماها.
2. `exercise-bank/service.ts` — شکستن به `packages.ts/files.ts/tags.ts/download.ts` + factory نازک.
3. `views/exercises.js::renderExercises` — جداسازی فیلترها/فهرست/جزئیات.
4. `bot-commands.ts::createBotCommandsSection` — هر خانوادهٔ دستور بات (لینک/نوبت/پیگیری/آگاهی) به ماژول خودش؛ `parseBotUpdate` همین حالا جدا و سالم است.
5. `games/service.ts` و `clinical-engine/service.ts` — الگوی شمارهٔ ۲.
بعد از هر گام، بنچمارک را دوباره بگیرید: انتظار P99/max رو به پایین، بدون تغییر LOC معنادار.

## ۶) چطور این سند زنده می‌ماند

- هر نسخه: `npm run bench:gate` در زنجیرهٔ گیت‌ها — سرخ شد یعنی بدهی تازه.
- هر فصل یا بعد از هر بازآرایی بزرگ: `npm run bench:complexity` + آپدیت آگاهانهٔ جدول §۲ با تاریخ.
- یافتهٔ تازه (مثلاً تابع تازهٔ ≥۱۵۰خط) باید در همان نسخه یا شکسته شود یا با دلیل در کامیت ثبت شود.
