# قوانین ثابت جلسه‌های توسعه — AGENTS

رأی کارفرما (۱۴۰۴/۰۸/۲۹)؛ تغییر این قوانین فقط با اعلام صریح کارفرما.
این سند مرجعِ هر جلسهٔ کاری روی مخزن است — پیش از هر کار خوانده می‌شود و بعد از هر کار رعایت.

## قانون ۱ — آخرین کار = کامیت

هیچ جلسه‌ای با کارِ commit‌نشده تمام نمی‌شود؛ آخرین عمل هر جلسه، کامیت و پوش روی شاخهٔ `rust` است.
چرایی: snapshot سندباکس بین جلسات ممکن است عقب برگردد؛ هر وضعیتی که فقط در سندباکس زندگی کند، از دست رفته است. مرجع حقیقت فقط مخزن است.

## قانون ۲ — بازسازی اول جلسه از آخرین کامیت

اول هر جلسه، پیش از هر خواندن/نوشتن:

```
git fetch origin && git reset --hard origin/rust
```

حتی اگر سندباکس سالم به‌نظر برسد — بازسازی ارزان است و از ادامهٔ کار روی وضعیت کهنه جلوگیری می‌کند.

## قانون ۳ — هر نمودار یا حفر دارد یا می‌رود

هر KPI، نمودار یا کارت تازه فقط با یکی از این سه شرط وارد محصول می‌شود:
۱. **حفر:** کلیک به فهرست واقعی پشت عدد (الگوی اجرا: `kpi(..., href)` مشترک در ui.js — POLISH-3 M2)؛
۲. **تصمیم مستند:** تست‌اش بنویسد «برای کدام تصمیمِ کدام کاربر است»؛
۳. **جایگزینی:** ورودش یک نمودار کهنهٔ کم‌ارزش را حذف کند.
شاخصِ فقط‌خواندنیِ بی‌حفر = پوستر = ممنوع.

## قانون ۴ — زمینهٔ محصول: مرکز دولتی، خدمات رایگان

نوبت و خدمات مرکز بدون هزینه است (تذکر کارفرما، ۱۴۰۴/۰۸/۲۹). پس:
- هیچ مسیر صورت‌حساب/بیمه/پرداختِ خانواده در محصول معنا ندارد — ساخته نشود و در نقدها پیشنهاد نشود؛
- ماژول مالی فقط بودجه/کمک/تراز دولتی است؛
- حلقهٔ نهادی = **پاسخگویی**: خدمت انجام‌شده ← پوشش و دسترس‌پذیری ← گزارش اداره؛
- شاخص‌های برتر مرکز در این زمینه: زمان انتظار، پوشش خدمات، عدم محرومیت — نه درآمد.
