# فلوی مدیریت نوبت‌ها و اطلاع‌رسانی بله

> نسخه ۱.۷ — اضافه شد («هدف سنجش» — هماهنگی بات با داشبورد سایت)
> ** — «هدف سنجش» (/goal یا دکمهٔ متنی):** فقط مدیر/منشی؛ همان شمارنده‌های
> امروز/۷روز/۳۰روز و همان کارت‌های هدف (سال/ماه/بازهٔ سفارشی — سرویس مشترک
> `application/dashboard/screening-goal.ts`) که داشبورد نشان می‌دهد، با پیشرفت
> «n از m (p٪)» و وضعیت هر هدف؛ کیبورد ثابت مدیر/منشی هم دکمهٔ «هدف سنجش» (کنار
> «وضعیت مرکز») گرفت. احراز هویت (ورود خودکار /کد اتصال) و گیت نقش‌های 
> دست‌نخورده ماندند؛ انکار نقش‌محور جدا: `bot_goal_denied`.
> نسخه ۱.۶ — اضافه شد (کیبورد ثابت ناوبری + «درباره مرکز» + ارتقای رمز PBKDF2)
> ** — دکمه‌های ثابت ناوبری:** با هر /start، ورود خودکار، اتصال با کد، /help و دستور ناشناخته،
> بات یک **کیبورد ثابت نقش‌محور** (reply keyboard) در پایین چت نصب می‌کند — همان ماتریس نقش‌های:
> مدیر/منشی: «نوبت‌های من | پیگیری‌های من»، «برنامه مرکز | لیست انتظار»، «بانک تمرین | وضعیت مرکز»، «درباره مرکز | راهنما»؛
> درمانگر: «نوبت‌های من | پیگیری‌های من»، «بانک تمرین»، «درباره مرکز | راهنما»؛
> والد: «نوبت‌های من | حضور فرزند»، «درباره مرکز | راهنما»؛ معلم کلاس: «نوبت‌های من | بانک تمرین»، «درباره مرکز | راهنما»؛
> مهمان: «راهنما»، «درباره مرکز». برچسب دکمه‌ها دقیقاً همان متن‌های پارس‌شدهٔ webhook است (بدون تایپ دستی).
> ** — «درباره مرکز» (/about یا دکمهٔ متنی «درباره مرکز»/«درباره ما»):** معرفی رسمی مرکز
> (سنجش و غربالگری، آموزش، توان‌بخشی، مداخلهٔ بهنگام رشدی) + مسیر اتصال گفتگو — برای همهٔ نقش‌ها حتی مهمان.
> ** — ارتقای امنیتی رمز ورود:** هش رمز کارکنان از SHA-256 بدون salt به **PBKDF2-HMAC-SHA256**
> (salt تصادفی ۱۶بایتی، ۲۵هزار تکرار، فرمت نسخه‌دار «pbkdf2$iter$salt$hash») ارتقا یافت؛
> هش‌های قدیمی در اولین ورود موفق شفافانه به فرمت جدید ارتقا می‌یابند (بدون شکستن bootstrap/seed).
> منوهای تو‌در‌تو (بانک تمرین/بازگشت تکلیف) دکمهٔ «↩ بازگشت» در همهٔ مراحل دارند.
> نسخهٔ ۱.۵ — (حلقهٔ بازگشت فایل؛ همراه معماری v3.5 / سامانه ۰.۳۱.۰)
> ** — بازگشت نتیجهٔ تکلیف:** خانواده عکس/فایل نتیجه را در چت بله می‌فرستد (بدون دستور و بدون منو) →
> پیوست خودکار به تکلیف باز (یا منوی انتخاب یا صفحهٔ بعدی در پنجرهٔ ۴۸ ساعت) → رکورد بازگشت + done شدن تکلیف
> + اعلان «نتیجهٔ تکلیف بازگشت» به ثبت‌کنندهٔ تکلیف + رویداد تایم‌لاین پرونده. طراحی کامل: EXERCISE-BANK.md §۴-ب.
> ** — بانک تمرین و ارسال تکلیف:** برچسب «بانک تمرین» + /bank برای همکاران مرکز و معلمان کلاس —
> منوی تو‌در‌تو (دستهٔ برچسب → فهرست → جزئیات → انتخاب دانش‌آموز → تأیید) و پیام «تکلیف جدید» به چت ولیّ
> با لینک دانلود امضاشده. طراحی کامل: EXERCISE-BANK.md.
> هدف: هر کاربر با **کد ملی یا شماره تلفن خود** در ربات بله احراز هویت می‌شود،
> **آخرین زمان نوبت‌های تنظیم‌شده برایش** را می‌بیند، و **معلم مرکز (همکار)**
> نوبت‌هایش را می‌بیند و **مدیریت می‌کند** (لغو با اطلاع‌رسانی خودکار).
> ** — بات اطلاع‌رسان:** پوش صبحگاهی «خلاصهٔ روز» + ورود امکانات سایت به بات
> («پیگیری‌های من» با دکمهٔ انجام، «حضور فرزند»، «وضعیت مرکز»).
> ** — بات نقش‌آگاه:** راهنمای بات برای هر مخاطب جداگانه (ماتریس نقش‌ها × دستورها)
> + «جستجوی دانش‌آموز» (/search — فقط همکاران) + «برنامهٔ مرکز» (/center — فقط مدیر/منشی).
> ** — لیست انتظار ↔ بات:** اعلان «نوبت خالی شد» به دفتر + دستور «لیست انتظار» (مدیر/منشی).

## ۰-الف) — ماتریس نقش‌ها × دستورها (فلو بر اساس نقش و احراز هویت)

هر chat بله بعد از احراز هویت (کد ملی/تلفن یا کد اتصال) یکی از نقش‌های زیر را دارد و
`resolveChatOwner` آن را با نقش کارمند (JOIN staff) برمی‌گرداند. `/help` و دستور ناشناخته
**فقط دستورهای همان نقش** را نشان می‌دهند — دستورهای دیگر یا انکار نقش‌محور می‌گیرند یا اصلاً در راهنما نیستند:

| نقش chat | «نوبت‌های من» /today /week | «پیگیری‌های من» | «حضور فرزند» | «وضعیت مرکز» | «برنامه مرکز» /center | «/search نام» | لغو نوبت با دکمه |
|----------|:---:|:---:|:---:|:---:|:---:|:---:|:---:|
| مدیر مرکز (staff: manager) | ✓ | ✓ | — | ✓ | ✓ | ✓ | ✓ (فقط نوبت خودش) |
| منشی (staff: secretary) | ✓ | ✓ | — | ✓ | ✓ | ✓ | ✓ (فقط نوبت خودش) |
| همکار متخصص (staff: therapist) | ✓ | ✓ | — | ✗ انکار | ✗ انکار | ✓ | ✓ (فقط نوبت خودش) |
| والد (student — bot_links/prefs) | ✓ | ✗ انکار | ✓ | ✗ انکار | ✗ انکار | ✗ انکار | — |
| معلم مدرسه (class — class_bot_links) | ✓ (کلاس) | ✗ انکار | — | ✗ انکار | ✗ انکار | ✗ انکار | — |
| بدون اتصال | راهنمای مهمان: مسیر ورود (کد ملی/تلفن) + /link | | | | | | |

قواعد:
- **«جستجوی دانش‌آموز» (/search نام)** — به ارث برده از جستجوی سراسری پنل؛ گیت همان مرز ورود به پنل
 (همهٔ همکاران، همهٔ دانش‌آموزانِ فعال). خروجی حداکثر ۵ نتیجه «نام — پایه» و **عمداً بدون کد ملی/تلفن** —
 PII در پنل می‌ماند، چون احراز هویت بات ضعیف‌تر است (§6). والد/معلم/مهمان → پیام انکار یا راهنمای مهمان.
- **«برنامهٔ مرکز» (/center یا «برنامه مرکز»)** — به ارث برده از بورد «روز کاری» پنل؛ فقط مدیر/منشی.
 برنامهٔ امروز همهٔ همکاران (ساعت — متخصص — دانش‌آموزان؛ لغوشده برچسب دارد)؛ سقف ۱۲ ردیف +
 خط «… و n مورد دیگر — نمایش کامل: پنل ← روز کاری». متخصص/والد/معلم → پیام انکار نقش‌محور.
- پرس‌وجوی خیلی کوتاه در /search (کمتر از ۲ نویسه) → همان راهنمای نقش (خط راهنمای /search را دارد).
- هیچ migration جدیدی لازم نشد — همهٔ گیت‌ها روی `resolveChatOwner` موجود سوارند.

## ۰-ب) — لیست انتظار ↔ بات (بستن حلقهٔ «نوبت خالی شد»)

### الف) اعلان «نوبت خالی شد» به دفتر

با هر **لغو نوبت** (از پنل یا از بات — ناظر `onCancelled`)، اگر **متقاضیِ بازی** در لیست انتظار باشد،
بات به همهٔ chatهای متصل **مدیر/منشی** پیام می‌دهد: متخصص، تاریخ/ساعتِ خالی‌شده و تا سه نام از متقاضیان:

| قاعده | مقدار |
|-------|-------|
| گیت | پرچم `notify_waitlist` (پیش‌فرض روشن؛ تنظیمات ← اعلان‌ها و بات) |
| شرط ارسال | حداقل یک ورودی باز (waiting/called) — لیست خالی → هیچ پیامی |
| مقصد | `staff_bot_links` متصل به staff با نقش manager/secretary (chatهای همکار/والد دریافت نمی‌کنند) |
| idempotent | `dedup_key = wl-free:{appointmentId}:{chatId}` — بازیابی + لغوی دوبارهٔ همان نوبت پیام تکراری نمی‌سازد |
| شکست | best-effort — خطای اعلان هرگز لغو نوبت را شکست نمی‌دهد |
| audit | `notification.waitlist_slot_freed` با بازیگر system |

### ب) دستور «لیست انتظار» (`/waitlist` یا دکمهٔ متنی «لیست انتظار»)

| دستور | دکمهٔ متنی | مخاطب | کار |
|-------|-----------|-------|-----|
| `/waitlist` | «لیست انتظار» | فقط مدیر/منشی | متقاضیانِ باز با **همان ترتیب پنل** (`orderWaitlist` دامنه: manual_order → urgent → FIFO): «نام (فوری/عادی — خدمت) — n روز در انتظار» — سقف ۸ ردیف + شمارندهٔ کل + ارجاع اقدام به پنل |

قاعدهٔ PII: برخلاف /search، نام متقاضیان برای دفتر نمایش داده می‌شود (همان چیزی که پنل به دفتر نشان می‌دهد)؛
تلفن/کد ملی در بات نمی‌آید. اقدام (تماس/برنامه‌ریزی/رد) عمداً در پنل می‌ماند — چرخهٔ full-listing در بات نیست.

### ج) — «بانک تمرین» (`/bank` یا دکمهٔ متنی «بانک تمرین»)

| مرحله | callback | کار |
|-------|----------|-----|
| ریشه | `exb:root` | [همهٔ تمرین‌ها] [اختلال‌ها] [پایه‌ها] [سایر برچسب‌ها] |
| دسته | `exb:cats:<d\|g\|o>:<page>` | برچسب‌های فعال آن دسته (تاکسونومی مشترک) |
| فهرست | `exb:lst:<cat>:<idx>:<page>` | تمرین‌های **منتشرشده** (۵تایی؛ عنوان روی دکمه) |
| دریافت | `exb:get:<idx>` | **یک کلیک = ارسال همهٔ فایل‌های تمرین پشت‌سرهم** (فایل‌های پیوست، یا فایل یگانهٔ legacy) + خلاصهٔ نتیجه: ✅ «هر N فایل یکجا ارسال شد» / ⚠️ «X از Y فایل ارسال شد» + دکمهٔ [ℹ️ جزئیات تمرین] و [↩ بازگشت] |
| جزئیات | `exb:item:<idx>` | عنوان/قالب/توضیح/برچسب‌ها + دکمهٔ جدا برای هر فایل (`exb:file:<idx>:<i>` تا ۴ فایل اول؛ legacy تک‌فایل `exb:lfile:<idx>`) — برای دریافت مجددِ تک‌فایل |

- جریان «ارسال تکلیف به دانش‌آموز از بات» حذف شد — callbackهای قدیمی (`exb:send:<idx>:<page>`، `exb:pick`، `exb:yes`، `exb:pkg`، `exb:pitem`) null می‌دهند.
- ارسال همهٔ فایل‌ها ترتیبی است (هر فایل با `sendDocument` + کپشن «📚 «عنوان تمرین»») و برای هر فایل موفق رویداد audit `exercise.file.sent_to_staff` ثبت می‌شود؛ خطای هر فایل بقیه را قطع نمی‌کند.
- گیت نقش در **هر** مرحله دوباره چک می‌شود (والد/مهمان → انکار نقش‌محور)؛ کلید `exercise_bank_enabled` غیرفعالی را با پیام مشخص اعلام می‌کند.

### د) — حلقهٔ بازگشت فایل (رسانهٔ خانواده → پرونده)

**بدون دستور جدید در راهنما:** خانواده فقط عکس یا فایل نتیجه را در چت بله می‌فرستد. پارسر پیام‌های رسانه‌ای را
(عکس با انتخاب بزرگ‌ترین سایز / سند) قبل از گارد متن می‌گیرد و کپشن را به‌عنوان «پیام خانواده» نگه می‌دارد.

| وضعیت تکلیف‌های فرزندانِ متصل | رفتار بات |
|------|------|
| دقیقاً یک تکلیف باز | پیوست مستقیم — بدون سؤال |
| چند تکلیف باز | دکمه‌های «نتیجهٔ کدام تکلیف است؟» (`sub:pick:<idx>`) — file_id + کپشن در state می‌ماند و بعد از انتخاب دانلود می‌شود |
| بدون باز، ولی بازگشتی در ۴۸ ساعت اخیر | صفحهٔ بعدیِ همان تکلیف (چند عکس طبیعی است؛ وضعیت done دست نمی‌خورد) |
| بدون باز و بدون بازگشتیِ تازه | «تکلیف بازی برای شما ثبت نشده است» + راهنما |

گاردها به ترتیب: chat بدون اتصال پرونده → «گفتگوی شما متصل نیست»؛ کلید قطع → «غیرفعال»؛ بدون توکن بله
(MediaFetcher null) → «دریافت فایل فعال نیست»؛ حجم > ۵۱۲KB → پیام کاهش کیفیت؛ سند با MIME ناجاز
(whitelist عکس/PDF/Word/Excel/متن — عکس همیشه مجاز) → پیام نوع؛ خطای دانلود → «دوباره بفرستید».

**پیوست موفق:** فایل در ObjectStore → رکورد بازگشت → وضعیت تکلیف «done» → پاسخ «نتیجهٔ تمرین «…» دریافت شد»
→ اعلان `homework_returned` به ثبت‌کنندهٔ تکلیف (همکار مرکز: چت‌های staff_bot_links؛ معلم: چت‌های class_bot_links
کلاس — dedup `hwret:{submissionId}:{chatId}`) → رویداد «نتیجهٔ تمرین بازگشت» در تایم‌لاین پرونده +
فیلتر «تکلیف تمرین» در پروفایل. ضد دوباره‌ثبت: state منوی انتخاب قبل از دانلود پاک می‌شود و وضعیت تکلیف
در لحظهٔ pick دوباره بررسی می‌شود.

## ۰) — بات اطلاع‌رسان (اطلاع‌رسانی فعال + به ارث بردن امکانات سایت)

### الف) پوش صبحگاهی «خلاصهٔ روز» — cron `0 4 * * *` (۰۷:۳۰ تهران)

هر صبح، بات بدون درخواست، برنامهٔ امروز را به همهٔ chatهای متصل پوش می‌کند:

| مخاطب | محتوا | قالب |
|-------|-------|------|
| همکار مرکز (chat متصل کارمند) | برنامهٔ امروز خودش (مثل /today) | `digest_staff` |
| خانواده (chat متصل دانش‌آموز — bot_links + prefs) | نوبت‌های امروز فرزندان (با نام متخصص؛ چند فرزند با زیرنویس) | `digest_family` |
| معلم مدرسه (chat متصل کلاس) | مراجعه‌های امروز دانش‌آموزان کلاس | `digest_class` |
| مسئولان پیگیری | یادآور پیگیری‌های عقب‌افتاده/امروز (حداکثر ۸ آیتم) | `followup_nudge` |

قواعد:
- **روزِ خالی پوش نمی‌گیرد** (بدون اسپم — شمارندهٔ `skippedEmpty` در خلاصه).
- **idempotent** با `dedup_key = digest:{date}:{chatId}` و `fu-nudge:{date}:{assigneeId}:{chatId}`.
- کلید خاموش/روشن در **تنظیمات ← اعلان‌ها و بات** (`notify_digest`، پیش‌فرض روشن).
- تریگر دستی: `POST /api/notifications/digest` (فقط مدیر) — خروجی `DigestSummary`.
- در `scheduled` ورکر، `event.cron === '0 4 * * *'` → چرخهٔ digest؛ بقیه → چرخهٔ یادآوری.

### ب) دستورهای جدید (به ارث برده از امکانات سایت)

| دستور | دکمهٔ متنی | مخاطب | کار |
|-------|-----------|-------|-----|
| `/followups` | «پیگیری‌های من» | همکاران مرکز | فهرست گروه‌بندی‌شدهٔ §13.4 (عقب‌افتاده/امروز/این هفته/بدون مهلت) + دکمهٔ inline **«انجام شد»** (حداکثر ۸) |
| `/attendance` | «حضور فرزند» | والدین | آمار ۳۰ روز اخیر هر فرزند متصل: حاضر/غایب/بدون ثبت/لغو (یک خط برای هر فرزند) |
| `/status` | «وضعیت مرکز» | فقط مدیر/منشی | جلسات امروز، حاضر/غایب امروز، لیست انتظار باز، پیگیری‌های عقب‌افتاده/امروز |

قواعد:
- **تکمیل پیگیری از بات** = همان قواعد دامنه (`open/in_progress → done`)؛ فقط **خودِ مسئول**؛
 callback `fudone:<id>`؛ بازیگر audit `bale-bot` (رویداد `followup.completed`)؛ تکرار/متعلق به دیگران → پیام رد.
 تکمیل یک‌مرحله‌ای است (برخلاف لغو نوبت) — عملیات قابل بازگشت از پنل و کم‌ریسک.
- «وضعیت مرکز» با **نقش کارمند از `resolveChatOwner`** (JOIN staff) گیت می‌شود؛ درمانگر → پیام انکار.
- «حضور فرزند» فقط chatهای متصل به پرونده (bot_links + prefs) — همان مرز حریم «نوبت‌های من».

## ۱) اصل طراحی — «اتصال خودسرانه ندارد، اما منشی هم لازم ندارد»

تا نسخه ۰.۱۲.۳ اتصال بات فقط با **کد اتصال ۶ حرفی** ممکن بود که منشی می‌ساخت.
این روش امن ولی کند بود (برای هر خانواده یک مرحله دستی). در مسیر دوم اضافه شد:

| مسیر | ورودی | برای چه کسی | وضعیت |
|------|-------|--------------|--------|
| **ورود خودکار** | کد ملی ۱۰ رقمی **یا** شماره همراه ۰۹… | والدین و همکاران | روش پیشنهادی |
| کد اتصال (/link CODE) | کد از منشی/مدیر | همه | همچنان فعال |
| کد کلاس | کد اتصال معلم مدرسه | معلمان مدارس | بدون تغییر |

قاعده تطبیق (به همین ترتیب):
1. **کارکنان**: `staff.national_id` یا `staff.phone` (کارمند اولویت دارد — چتِ کسی که هم کارمند است هم والد، به عنوان همکار شناخته می‌شود)
2. **دانش‌آموزان**: `students.national_id` یا `students.guardian_phone`
 - شماره تلفن مشترک (پدر با دو فرزند) → **همهٔ فرزندان با هم** به همان چت متصل می‌شوند
 - چند کارمند با یک شماره → پیام «کد ملی خود را بفرستید»
3. هیچ تطابقی → پیام راهنما + معرفی مسیر /link

فرمت‌های پذیرفته‌شده (ارقام فارسی/عربی خودکار نرمال می‌شوند):
- ۱۰ رقم → کد ملی (اگر با کد ملی پیدا نشود، به‌عنوان موبایلِ بدون صفر اول هم امتحان می‌شود)
- ۱۱ رقم شروع با ۰۹ → موبایل
- ۱۲ رقم شروع با ۹۸ (یا +۹۸) → موبایل
- قالب‌های دیگر → پیام راهنما (نه سکوت)
- متن مخلوط حرف‌وعدد → نادیده (نویز؛ بات اسپم نمی‌فرستد)

## ۲) جریان والد

```
/start → «کد ملی یا شماره همراه را بفرستید»
کد ملی فرزند / شماره والد
 → «✅ اتصال انجام شد + فهرست پرونده‌های متصل»
«نوبت‌های من»
 → نوبت‌های scheduled از همین لحظه تا ۱۴ روز بعد، همهٔ فرزندان:
 ۰۹:۰۰ دکتر علی رضایی — فرزند: پویا امیدی
 ۱۴:۰۰ مریم احمدی — فرزند: پریا امیدی
 → یادآوری: «برای تغییر یا لغو با دفتر مرکز تماس بگیرید»
/today · /week → برنامهٔ امروز/هفته (مثل قبل)
```

اطلاع‌رسانی خودکار (صف `notifications` — بدون تغییر معماری):
- **ثبت نوبت جدید** → «✅ نوبت جدید ثبت شد»
- **جابه‌جایی** → «✏️ تغییر زمان نوبت» (قبلی → جدید)
- **لغو** → «❌ لغو نوبت» (باگ.3 رفع شد: تا قبل از والد پیام لغو دریافت نمی‌کرد)
- **یادآوری** → طبق `reminder_hours_before` هر پرونده (cron 20:30 و 10:00 تهران)
- **غیبت** → «🔔 اطلاع‌رسانی غیبت»

## ۳) جریان همکار (معلم مرکز)

```
کد ملی / شماره همراه همکار
 → «✅ اتصال انجام شد — همکار مرکز: دکتر علی رضایی»
«نوبت‌های من»
 → نوبت‌های scheduled از همین لحظه تا ۷ روز بعد
 ۰۹:۰۰ علی محمدی
 [لغو ۰۹:۰۰] ← دکمه inline زیر هر نوبت آینده (حداکثر ۸ دکمه)
تأیید دومرحله‌ای:
 [لغو ۰۹:۰۰] → «⚠️ لغو این نوبت؟... با لغو، به خانواده اطلاع داده می‌شود»
 → [بله، لغو شود]
 → «✅ نوبت لغو شد... به خانواده اطلاع داده شد»
```

قواعد مدیریت از بات:
- فقط **نوبت خودِ همکار** (بررسی `appointment.staff_id === owner`) — چت دیگران رد می‌شود
- فقط **نوبت scheduled** — نوبت لغوشده → پیام «تعلق ندارد/موجود نیست»
- لغو با **version فعلی** انجام می‌شود؛ اگر هم‌زمان در پنل تغییر کرده باشد → پیام «دوباره تلاش کنید» (۴۰۹)
- لغو از بات = لغو از پنل: `audit_log` با بازیگر `bale-bot` + اعلان خودکار به والد
- جابه‌جایی/ساخت نوبت از بات عمداً پیاده نشده (موتور تداخل + انتخاب اسلات در پنل بهتر است)

## ۴) جریان اطلاع‌رسانی (بدون تغییر معماری)

همهٔ پیام‌ها از همان صف `notifications` می‌گذرند (dedup با `dedup_key`، تلاش مجدد،
آمار در پنل). اتصال خودکار فقط مقصدهای جدید به همان صف اضافه می‌کند:

```
رویداد نوبت (create/move/cancel/absent/reminder)
 → observer چرخه حیات (api-routing)
 → صف notifications (bale یا internal در dev)
 → dispatchPending → کانال بله (tapi.bale.ai) → والد/همکار/معلم مدرسه
```

## ۵) راه‌اندازی (deployment)

```bash
npx wrangler secret put BALE_BOT_TOKEN # توکن از @BotFather بله
npx wrangler secret put BALE_WEBHOOK_SECRET # رشته تصادفی
# ثبت webhook (یک بار):
curl "https://tapi.bale.ai/bot<$TOKEN>/setWebhook" \
 -d "url=https://<دامنه-ورکر>/webhook/bale/<BALE_WEBHOOK_SECRET>"
```

وضعیت اتصال بات همیشه در **تنظیمات ← اعلان‌ها و بات** دیده می‌شود.

## ۶) محدودیت‌های پذیرفته‌شده (تصمیم کاربر: سادگی اول است)

- ورود با کد ملی/تلفن **بدون رمز یک‌بارمصرف** است؛ هر کسی که این اطلاعات را بداند
 می‌تواند چت خود را متصل کند. مسیر ارتقای پیشنهادی برای آینده: تأیید پیام در بات به
 شماره ثبت‌شده (OTP رایگان داخل خود بله) — بدون تغییر اسکیما.
- «مدیریت» همکار در بات = دیدن + لغو. ساخت/جابه‌جایی در پنل وب انجام می‌شود.
- حداکثر ۸ دکمهٔ لغو در هر پیام (نوبت‌های بیشتر با /today یا /week قابل تفکیک‌اند).
