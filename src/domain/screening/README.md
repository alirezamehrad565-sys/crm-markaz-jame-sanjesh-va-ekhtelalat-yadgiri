# ماژول سنجش روزانه (غربال نوآموزان بدو ورود به دبستان)

## مسئله
مرکز هر روز تعدادی «نوآموز سنجشی» می‌بیند که بدو ورود به دبستان غربال تخصصی
می‌شوند: **بینایی، شنوایی، هوش، جسمی‌حرکتی**. عمده بچه‌ها سالم‌اند (فقط حدود ۱٪
ارجاع می‌شوند). هدف: منشی/مدیر در کمترین زمان، نام هر نوآموز را همان روز ثبت و
«برچسب» بزند؛ بعداً پیگیری‌ها بر حسب برچسب انجام شود.

## اصل طراحی — بدون پروفایل
- **یک باکس**: تایپ «نام و فامیل» + لمس برچسب‌ها → ثبت. هدف < ۱۰ ثانیه به‌ازای هر بچه.
- **هر چیزی با `#` برچسب است**: در همان باکس اسم — مثل `#مرضیه_احمدی` (کارمند
  سنجش‌گر) یا `#مهدکودک_ستاره` (مهدکودک مبدأ). خط‌زیر/خط‌تیره = فاصله.
- **۶ برچسب ثابت** با تاگل یک‌لمسی: ارجاع تخصصی بینایی / شنوایی / هوش /
  جسمی‌حرکتی / عدم همکاری / نداشتن ثبت‌نام. **عادی = بدون برچسب.**
- هشتگ کوتاه که با نام برچسب ثابت بخواند (`#بینایی`) خودکار به همان برچسب ثابت resolve می‌شود.
- برچسب‌ها **ماندگار** هستند — پیگیری بعدی (تماس خانوادهٔ ارجاعی‌ها و…) بر حسب برچسب فیلتر می‌شود.

## RBAC
| عملیات | نقش |
|---|---|
| GET لیست/KPI و برچسب‌ها | همهٔ نقش‌ها (نمای دفتر در nav فقط برای manager/secretary) |
| POST / PATCH / DELETE | فقط `manager` و `secretary` |

## API
| مسیر | توضیح |
|---|---|
| `GET /api/screening?from&to&q&tag` | فهرست + KPI روی همان فیلتر (tag = جدا با کاما، معنای OR) |
| `GET /api/screening/tags` | همهٔ برچسب‌های مصرف‌شده + شمارش (برای «برچسب‌های اخیر» و فیلتر مدیر) |
| `POST /api/screening` | `{ name, tags?, day? }` — day پیش‌فرض امروز تهران |
| `PATCH /api/screening/:id` | `{ name?, tags? }` |
| `DELETE /api/screening/:id` | حذف ردیف اشتباه (با audit) |

## KPI (سِمت سرور، pure)
`total` / `normal` (بدون برچسب) / `referrals` (حداقل یک برچسب ارجاع) /
`referralRate٪` / `noCoop` / `noReg` / `perTag[]` / `byDay[]` — همه روی
ورودی‌های فیلترشدهٔ همان درخواست.

## داده
جدول `screening_entries` (migrations/0025): `name` آزاد، `day` (YYYY-MM-DD
تهران)، `tags` (آرایهٔ JSON)، `created_by` + audit. حذف Hard با audit مجاز است
(لاگ عملیاتی روزمره است، نه سند بالینی).

## فایل‌ها
- `types.ts` — فهرست برچسب‌های ثابت + تایپ‌ها
- `pure.ts` — پارس `#`، resolve، sanitize، فیلتر OR، KPI (کاملاً تست‌پذیر)
- `service.ts` — D1 + audit (مالک جدول)
- `routes.ts` — REST + RBAC
- `__tests__/` — pure + e2e (RBAC، CRUD، فیلتر، KPI)

## UI (پنل)
`#/screening` — دو تب با زبان طراحی موجود (کرم/آبی، وزیرمتن):
1. **ثبت روزانه** — باکس واحد + پیش‌نمایش زنده + چیپ‌های تاگل + برچسب‌های اخیر + لیست امروز (ویرایش/حذف + هشدار ثبت تکراری)
2. **گزارش و KPI (مدیر)** — بازهٔ امروز/۷/۳۰ روز/همه/دلخواه + فیلتر برچسب + پریست «نیازمند پیگیری» + جستجو → کارت‌های KPI، روند روزانه، تفکیک برچسب‌ها (کارمند/مهدکودک/وضعیت‌ها)، لیست پیگیری، خروجی CSV
